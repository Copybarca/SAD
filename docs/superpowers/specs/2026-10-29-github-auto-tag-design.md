# Автоматическое SemVer-тегирование в GitHub

## Намерение

Подключить к SAD только автоматическое создание SemVer-тегов. Workflow не
собирает Java-приложение, не запускает тесты, не создаёт Docker-образы и не
выполняет деплой.

## События

Workflow запускается на каждый push в `develop`, `main` или `master`.

- После слияния pull request исходная ветка определяется через GitHub API.
- При прямом push исходной считается целевая ветка, поэтому версия повышается
  на patch.
- Push тега не запускает workflow.

## Расчёт версии

Workflow повторно использует `ci/version.sh` и `ci/auto-tag.sh` и передаёт им
GitHub-контекст через совместимые переменные окружения.

- `feature!/*` повышает major.
- `feature/*` повышает minor.
- `fix/*`, `hotfix/*`, `perf/*`, `refactor/*` и `revert/*` повышают patch.
- `doc/*`, `docs/*`, `test/*`, `chore/*`, `build/*` и `ci/*` не создают тег.
- Прямой push в `develop`, `main` или `master` повышает patch.
- При отсутствии SemVer-тегов создаётся `1.0.0`.
- Если текущий коммит уже имеет SemVer-тег, новый тег не создаётся.

## GitHub workflow

Создаётся `.github/workflows/auto-tag.yml`. Checkout получает полную историю и
теги. Для merge workflow получает исходную ветку вызовом GitHub API для
текущего commit SHA; если связанного merged pull request нет, используется
`GITHUB_REF_NAME`.

Workflow получает минимальные разрешения:

- `contents: write` для отправки тега;
- `pull-requests: read` для определения исходной ветки.

- Существующие правила и POSIX-скрипты остаются единственным местом расчёта
